# Idea to Linear

Start: “Users should be able to create reusable evidence reports.” Use `issue-workflow`, or invoke the individual skills as needed.

1. `investigate-issue`: inspect existing report/search/query concepts, actual behavior, constraints, and related issues.
2. `shape-feature`: settle the product decisions evidence cannot answer. Preserve facts, choices, assumptions, and open questions separately.
3. `design-user-flow`: define entry, success, alternate/recovery behavior, and relevant states.
4. `wireframe-feature`: add a reviewable sketch if UI materially matters; skip UI artifacts for backend-only work.
5. `write-feature-spec`: synthesize the product contract with traceable requirements and observable criteria.
6. `review-feature-spec`: challenge the current artifacts and resolve blockers; changed semantics require renewed review.
7. `publish-linear`: create within the requested scope and verify the write, or return complete ready-to-paste content.
8. `handoff`: provide durable references and the next action for native Pstack or further shaping.

Stop dependent work at an unresolved consequential product choice. Do not invent semantics to reach the end of the sequence. Store only useful artifacts using the [artifact convention](../docs/artifacts.md).
